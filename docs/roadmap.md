# 六周路线图

每一行都可以直接变成一条 GitHub Issue。做完打勾，别跳步——
第 2 周不出图，这个项目大概率会烂尾。

## 第 0 周：立项（2–3 天）

- [ ] 用一句话写清：**给谁**解决**什么问题**
- [ ] 定一个可量化的成功标准，例如"mAP50 ≥ 0.75 且单帧 < 50ms"
- [ ] 确认数据来源（自拍 / 公开数据集 / 合作方），写进 README
- [ ] 把本仓库推到 GitHub，CI 跑绿
- [ ] 建看板：Todo / In Progress / Done

## 第 1 周：数据

- [ ] 采集 ≥ 500 张（含 ≥ 50 张负样本）
- [ ] 按 `docs/labeling.md` 定稿类别定义
- [ ] 标 50 张，自查歧义，修文档
- [ ] `python -m src.prepare stats` 无报错
- [ ] `python -m src.prepare dups` 无跨 split 泄漏
- [ ] 切分 train/val/test，比例 8:1:1

## 第 2 周：基线（关键节点）

- [ ] `python -m src.train --smoke` 跑通
- [ ] 用 COCO 预训练权重直接推理，记录"零样本"指标
- [ ] 全量微调一轮，`python -m src.evaluate` 出第一张对比表
- [ ] **README 里放一张预测图**，哪怕效果很差
- [ ] 写下第一版"失败案例"

> 到这里你已经有一个"能做 demo"的东西了。后面都是加分项。

## 第 3 周：把指标做上去

- [ ] 至少 3 组对照实验：数据增强 / imgsz / 模型档位（n→s）
- [ ] 每组实验都 `--tag` 一个名字，进 `results/metrics.md`
- [ ] 分析 badcase：漏检多还是误检多？小目标还是低对比度？
- [ ] 针对性地补数据（不是盲目加轮数）

## 第 4 周：训练策略

- [ ] 冻结 backbone 微调 head，对比全量微调
- [ ] 处理类别不平衡（过采样 / focal loss / 补样本）
- [ ] 如果用了分割：对比检测 vs 分割的 mAP 与速度
- [ ] 把"我试了什么、什么有效、什么无效"写成一节

## 第 5 周：部署

- [ ] `python -m src.export` 导出 ONNX
- [ ] `--int8` 量化，记录精度损失
- [ ] `python -m src.benchmark` 测 p50/p95 延迟与体积
- [ ] `python -m src.app` 起 Demo，录一段 GIF
- [ ] Dockerfile 能构建并跑起来

## 第 6 周：包装

- [ ] README 补齐：架构图、指标表、失败案例、后续计划
- [ ] 录 3 分钟讲解视频（B 站 / YouTube）
- [ ] 写一篇技术博客，讲清楚"为什么这么做"
- [ ] 发到相关社区（V2EX / 即刻 / Reddit r/computervision），收集反馈
- [ ] 准备面试话术：问题→数据→基线→改进→归因→局限

## 面试自检清单

能不看稿回答这六个问题，项目就算讲清楚了：

1. 你的验证集怎么保证和训练集不泄漏？
2. 这个 mAP 提升是真实的还是过拟合？你怎么排除？
3. 为什么选这个模型档位，而不是更大/更小的？
4. 量化掉的那几个点，掉在哪类目标上？
5. 如果给你 10 倍数据和 10 倍算力，你先改什么？
6. 这个方案上线后，最可能怎么坏？
