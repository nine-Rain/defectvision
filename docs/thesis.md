# 论文对照表：流程图 → 代码

这份文档把开题/论文里的那张系统流程图，逐块映射到仓库里的实现，
方便写论文时直接引用模块名和文件路径，也方便答辩时现场打开对应代码。

## 一、流程图 → 代码

| 流程图模块 | 仓库里的实现 | 说明 |
| --- | --- | --- |
| ① 数据层 · 数据采集 | `scripts/fetch_dataset.py` | 从 HF 镜像拉 MSDD / NEU-DET，断点续传、429 退避 |
| ① 数据层 · 缺陷标注 | `docs/labeling.md` | 标注规范、一致性检查、常见坑 |
| ① 数据层 · 预处理与增强 | Ultralytics 内置增强；CNN 路线见 `src/data/yolo_dataset.py` | 翻转/裁剪/色彩抖动由框架完成 |
| ① 数据层 · 数据集划分 | `src/prepare.py` + 各数据集自带的 split | `dups` 子命令专治跨 split 泄漏 |
| ② 改进 CNN · ResNet 骨干 | `src/models/detector.py::build_backbone` | ResNet50，取 layer1~layer4（C2~C5） |
| ② 改进 CNN · FPN 多尺度融合 | 同上（`torchvision` 的 `BackboneWithFPN`） | 自顶向下 + 3x3 平滑，统一 256 通道，5 个尺度 |
| ② 改进 CNN · CBAM 注意力 | `src/models/cbam.py` | 通道注意力 + 空间注意力，逐层插在 FPN 输出后 |
| ② 改进 CNN · 检测与分类 | `FasterRCNN` 头 | RPN 出候选框，ROIHead 做分类 + 回归 |
| ③ 缺陷等级判定 | `src/grade.py` + `configs/grading.yaml` | 四项特征加权 + 一票否决，输出 I~IV 级 |
| ④ 系统应用层 | `src/ui/app.py` | PyQt5：导入、检测、判级、可视化、报告、批量 |
| ⑤ 实验验证层 | `results/metrics.md`、`results/*.json` | 指标由脚本生成，不手抄 |
| ⑥ 成果输出 | 本仓库 + 论文 | 代码、模型权重、实验记录都在版本控制里 |

## 二、模型结构（写进论文的正文）

```
输入 512x512x3
  └─ ResNet50
       ├─ layer1 → C2  256ch  stride 4
       ├─ layer2 → C3  512ch  stride 8
       ├─ layer3 → C4 1024ch  stride 16
       └─ layer4 → C5 2048ch  stride 32
  └─ FPN：C5 上采样逐级相加 → P2..P6（统一 256ch）
  └─ CBAM ×5：每个尺度独立一组（通道注意力 + 空间注意力）
  └─ RPN：每个尺度 3 种长宽比，生成候选框
  └─ ROI Align (7x7) → 分类头 + 回归头
输出：类别 + 边界框（可扩展为掩码）
```

参数量约 41.4M（ResNet50-FPN-FasterRCNN + CBAM），可在 `python -m src.train_cnn` 启动日志里看到。

**为什么这么选**（答辩会被问）：
- ResNet50 有 ImageNet 预训练且特征层次清晰，适合 200~512 的中小图；
- FPN 解决"缺陷尺度差异大"——划痕细长、氧化成片；
- CBAM 的通道注意力筛"哪些特征通道对缺陷有用"，空间注意力压背景纹理（金属拉丝纹理极易被误检）；
- 检测头用成熟实现，把变量控制在 backbone 上，消融实验才说得清。

## 三、实验设计

### 数据集

| 数据集 | 规模 | 类别 | 用途 |
| --- | --- | --- | --- |
| MSDD（金属零件） | 1,195 / 150 / 150 | 6 | 主实验、判级演示 |
| NEU-DET（热轧钢带） | 1,458 / 162 / 180 | 6 | 泛化性验证（已接入） |

NEU-DET 的获取：官方页面只提供人工申请，实际可用的是 GitHub 上的 YOLO 整理版，
经代理下载后校验通过（4,189 个框，无缺失标签）：

```powershell
# 已下载并整理到 data/neu-det，配置见 configs/dataset.neu-det.yaml
python -m src.prepare stats --config configs/dataset.neu-det.yaml
```

如果想换一份数据重来，脚本支持任意 Hugging Face 上的 YOLO 数据集：

```powershell
python scripts/fetch_dataset.py --repo KeenForgeAI/NEU-DET-corrected --out data/neu-det --slug neu-det
```

两份数据的缺陷形态差异很大（圆件 vs 钢板），跨数据集结果能支撑"方法可迁移"的结论。

### 对比模型（按答辩意见：对比现有成熟方法，而非经典 CNN 分类器）

### 分级实验（答辩老师说的"很少有人做"的部分）

用标注框按同一套规则算出"参考等级"，再和模型判出的"系统等级"对比。
MSDD test，150 张，置信度阈值 0.25：

| 模型 | mAP50 | 完全一致率 | ±1 级内一致率 | IV 级召回 | 低等级误杀率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| YOLOv8s | **0.588** | **83.3%** | **86.7%** | 93.9% | **6.2%** |
| YOLO11n | 0.559 | 82.7% | 84.7% | 92.9% | 9.4% |
| CNN（50ep+增强） | 0.574 | 73.3% | 75.3% | 94.9% | 59.4% |
| CNN（20ep） | 0.476 | 65.3% | 66.7% | 98.0% | 93.8% |

混淆矩阵（行=参考，列=系统）：

```
YOLO11n           系统: 合格   I   II  III   IV
参考 合格              24    0    0    0    1
     I                1    4    0    0    2
     II               5    1    4    0    8
     III              0    0    0    1    1
     IV               4    2    1    0   91
```

三条结论，每一条都能单独成段：

1. **mAP 与判级可用性不成正比**：增强后的 CNN mAP50（0.574）**高于** YOLO11n（0.559），
   但判级完全一致率低 9 个百分点，误杀率是它的 6 倍。
   mAP 榜上的名次，在分级任务上会翻盘。
2. **IV 召回高不等于好**：CNN 的 94.9% 是靠"几乎都判致命"换来的，
   59.4% 的正常/轻微件被判成严重——产线上等于把好件当废品。
3. **误差以跨级为主**：±1 容忍只比完全一致多 1~2 个百分点，
   说明错误不是"差一点"，而是直接判错档。这与 CNN 框过大的问题完全对应。

> 这张表就是"量化分级"方向的证据：**检测指标不能直接代表系统可用性**。
> 也说明引入判级层不是"多此一举"，而是暴露了纯 mAP 评估看不到的风险。

### 消融实验

固定数据、轮数、输入尺寸，只改 CBAM 开关：

```bash
python -m src.train_cnn --name cnn-nocbam --no-cbam --epochs 20
python -m src.train_cnn --name cnn-cbam   --cbam    --epochs 20
python -m src.evaluate --compare
```

表格由 `results/metrics.md` 自动生成，包含 mAP50、mAP50-95、Recall、参数量、体积。

### 实验结果（test，均为同一套评估脚本产出）

| 数据集 | 模型 | mAP50 | mAP50-95 | 参数量 |
| --- | --- | ---: | ---: | ---: |
| MSDD | YOLO11n | 0.559 | 0.384 | 2.6 M |
| MSDD | ResNet50+FPN（20ep） | 0.494 | 0.262 | 41.4 M |
| MSDD | ResNet50+FPN+CBAM（20ep） | 0.476 | 0.248 | 41.4 M |
| MSDD | ResNet50+FPN（50ep+增强） | 0.516 | 0.275 | 41.4 M |
| MSDD | ResNet50+FPN+CBAM（50ep+增强） | 0.574 | 0.298 | 41.4 M |
| NEU-DET | YOLO11n | 0.749 | 0.404 | 2.6 M |
| NEU-DET | ResNet50+FPN+CBAM | 0.667 | 0.299 | 41.4 M |

**核心结论（按重要性）**

1. **数据增强是这份实验里最有效的单项改进**：同一个 CBAM 模型，
   mAP50 从 0.476 涨到 0.574（+0.098）。数据量只有 1.2k 时，增强比换结构划算。
2. **CBAM 的效应不稳定**：20 轮时无 CBAM 更好（-0.018），50 轮带增强时 val 上无 CBAM 更好、
   test 上 CBAM 更好。val/test 结论相反，说明差异落在 150 张验证集的抽样波动（±0.02~0.03）里，
   **不足以支撑任何方向性结论**。
3. **自研两阶段模型的短板是定位精度**：MSDD 上 mAP50 反超 YOLO（0.574 vs 0.559），
   但 mAP50-95 明显更低（0.298 vs 0.384）。
4. **纹理型缺陷是共同难点**：MSDD 的 `scratch`（掩码 mAP50 0.187）、
   NEU 的 `crazing`（0.37），都是低对比度、边界模糊的纹理缺陷。

第 2 条是"没有结论"的结果。写进论文时要如实呈现，并说明方法学缺陷：
**前几轮实验没有固定随机种子，且只跑了单种子**。`--seed` 已加入训练脚本，
可发表的做法是 3 个种子取均值±标准差。这不是遮丑，是把实验设计的边界讲清楚。

## 四、判级规则怎么解释

判级严格按开题报告的定义实现，**不是加权评分**，而是四个判据各自定级、取最高（就高不就低）：

| 等级 | 面积占比 | 缺陷数量 | 裂纹 | 处置 |
| --- | --- | --- | --- | --- |
| I 级 轻微 | ≤ 0.5% | ≤ 2 | 无 | 合格，放行留档 |
| II 级 中度 | 0.5%~2% | 3~5 | 非贯穿性短裂纹 | 让步接收，返修后复检 |
| III 级 严重 | 2%~5% | 6~10 | 长度超限 | 返工，二次全检 |
| IV 级 致命 | > 5% | > 10 | 贯穿性裂纹 | 判废，追溯同批次 |

补充规则：
- **连片密集**：数量 ≥ 4 且最近间距 < 2% 对角线 → 直接 IV；
- **面积按框并集计算**，重叠检测不会重复计数；
- **裂纹长度**按外接框长边 / 图像长边归一化，30% 判 III、80% 判 IV。

为什么不用加权评分：加权会把"数量多但面积小"和"面积大但只有一处"平均成同一个分数，
掩盖了真正的风险项。开题报告里写的"就高不就低"才是工业质检的通行做法——
任何单项超标都不能被其他项稀释。

`configs/grading.yaml` 里每一项都可改，答辩时可以现场调阈值演示等级变化。
综合得分仅作展示，不参与定级。

## 五、局限（论文的"不足与展望"可以直接用）

1. 标签质量是上限：MSDD 的框普遍偏松，mAP50-95 上不去；
2. 两阶段模型推理慢于 YOLO，实时性要求高的产线需要换单阶段 + 量化；
3. 判级阈值来自开题时的经验设定，没有用真实工艺数据做标定；
4. 公开数据集没有"裂纹"类别，用 `crazing` / `scratch` 做了近似映射；
5. 只在两个公开数据集上验证，缺少真实产线的长期数据。
